# Design: menu-bar switcher for parallel Claude Code agents

Working title: **Deck** (можно переименовать — это не фиксировано).
Date: 2026-11-08 · Platform: macOS (menu-bar), SwiftUI.

## Intent / why

Пользователь держит несколько агентов Claude Code параллельно — обычно 3 консоли
на одном проекте и 3 на другом, все работают одновременно. Сейчас нет одного места,
чтобы (а) быстро прыгнуть в нужную консоль и (б) с одного взгляда увидеть статус,
главное — что агент **закончил работу** или **ждёт ввода**. Приходится вручную
обходить все окна. Нужен лёгкий «пульт» в menu-bar: запустить, переключиться,
увидеть статус, получить пинг. Проще, чем coucou.

## Core model (решено с пользователем)

**Приложение само запускает агентов в iTerm2.** Раз оно их запускает — оно с самого
начала владеет связью «эта консоль ↔ этот агент», поэтому клик по строке в шторке
гарантированно фокусит нужную панель iTerm2. Редактирование кода/файлов остаётся в
WebStorm отдельно; Deck — это пульт, а не IDE и не терминал. Проблема переключения
между вкладками встроенного терминала WebStorm (нерешаемая чисто через API) таким
образом просто обходится.

## Goals

- Один список всех живых агентов, сгруппированный по проекту (папке).
- Каждому агенту — своё имя (задаётся при запуске, редактируется позже).
- Статус в реальном времени: работает / ждёт тебя / закончил / упал / закрыт.
- Короткая строка «чем занят сейчас» (имя текущего инструмента, напр. «Editing foo.ts»).
- Клик по строке → мгновенный фокус нужной панели iTerm2.
- Нативное уведомление, когда агент **закончил** (Stop) и когда **ждёт ввода**
  (Notification/permission).
- Кнопка «новый агент»: выбрать папку проекта + имя → запустить `claude` в iTerm2.

## Non-goals (v1)

- Не встраиваем терминал и не заменяем его; не становимся IDE.
- Не управляем WebStorm и не переключаем его вкладки.
- Не поддерживаем другие терминалы (Terminal.app, tmux, VS Code) в v1.
- Нет облака/мультимашинности и нет iPhone-клиента в v1 — но архитектуру не ломаем
  против будущего iPhone-компаньона (Swift-модель переиспользуема).

## Anti-goals (что считаем провалом, даже если «работает»)

- Разрастание фич до уровня coucou. Если экран перестаёт читаться за 1 секунду — провал.
- Хрупкие трюки (эмуляция клавиш/Accessibility для чужих окон) ради «универсальности».

## Constraints

- У пользователя уже навешаны хуки Claude Code на все события (`cc-status` для iTerm2 +
  pandev). Наш хук **добавляется рядом**, ничего существующего не ломая.
- Переключение требует разрешения macOS Automation (управление iTerm2). Accessibility
  НЕ требуется (сознательно выбран iTerm2-путь). Нужно разрешение на уведомления.

## Approaches considered

**Механизм переключения**
- (A) **Приложение запускает и владеет консолями в iTerm2** — выбрано. Надёжный фокус
  конкретной панели по её session id, связь известна с момента запуска.
- (B) Цепляться к произвольным существующим терминалам, включая WebStorm, через
  Accessibility — отклонено: хрупко, ломается на обновлениях, требует AX-разрешений.
- (C) Только подъём окна (без выбора точной вкладки) — отклонено: не решает главный
  кейс «3 вкладки в одном окне».

**Стек приложения**
- **SwiftUI `MenuBarExtra`** — выбрано: лёгкое, нативный menu-bar и уведомления, прямой
  доступ к iTerm2, путь к iPhone через переиспользование Swift. Tauri/Electron —
  отклонено: тяжелее для menu-bar, не ведёт к iPhone.

**Транспорт статусов (хук → приложение)**
- **Файл-вотчинг: хук дописывает JSON-строки в `~/.deck/events.jsonl`, приложение
  слушает папку через FSEvents** — выбрано для MVP: просто и надёжно, без сети.
- Локальный HTTP-сервер в приложении — отложено (возможный апгрейд, если понадобится
  двусторонность).

**Управление iTerm2**
- **AppleScript (`osascript`/`NSAppleScript`)** для запуска и фокуса — выбрано для MVP,
  без зависимости от Python.
- iTerm2 Python API — путь апгрейда, если AppleScript упрётся в лимиты фокуса.

## How it works (architecture)

**Идентичность.** При запуске агента приложение генерирует стабильный `agent_id` (uuid),
запоминает имя и папку, и экспортирует переменную окружения `DECK_AGENT_ID=<uuid>` в
запускаемую сессию. При старте iTerm2-сессии через AppleScript получаем её `session id`
и сохраняем связь `agent_id ↔ iterm_session_id`. На событии `SessionStart` хук сообщает
Claude `session_id`, достраивая связь `agent_id ↔ claude_session_id ↔ cwd`.

**Запуск (AppleScript).** Создать в iTerm2 вкладку/панель с рабочей папкой проекта и
выполнить команду запуска `claude` (с прокинутым `DECK_AGENT_ID`). Получить и сохранить
`session id` вкладки.

**Хук.** Один небольшой скрипт (shell, без зависимостей), добавляемый в массивы хуков
`SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Notification`, `Stop`,
`StopFailure`, `SessionEnd`. Он читает JSON события со stdin, берёт `hook_event_name`,
`session_id`, `cwd`, `transcript_path` и env `DECK_AGENT_ID`, и дописывает одну
JSON-строку в `~/.deck/events.jsonl`. Приложение предлагает кнопку «установить хуки»,
которая безопасно мёржит это в `~/.claude/settings.json`, не трогая существующие
`cc-status`/pandev.

**Маппинг событий → статус.**
- `SessionStart` → готов/простаивает
- `UserPromptSubmit` / `PreToolUse` / `PostToolUse` → работает (+ активность = имя
  инструмента и короткий аргумент)
- `Notification` → ждёт тебя (разрешение/ввод) → **уведомление**
- `Stop` → закончил ход / ждёт тебя → **уведомление**
- `StopFailure` → ошибка
- `SessionEnd` → закрыт

**Фокус по клику.** Активировать iTerm2 и `select` вкладку/окно по сохранённому
`iterm_session_id`.

**UI.** `MenuBarExtra`: иконка в меню-баре отражает агрегат (есть ли «ждёт тебя» /
«закончил, непросмотренное»). В дропдауне — секции по проектам; строка = цветная точка
статуса + имя + строка активности + время с последнего изменения. Клик → фокус.
Действия строки: переименовать, (опц.) закрыть. Сверху — кнопка «новый агент».

**Персистентность.** Реестр агентов (agent_id, имя, папка) и кастомные имена хранятся
в приложении (SwiftData или JSON). Переживают перезапуск; при старте сверяемся с живыми
сессиями, мёртвые помечаем закрытыми.

## Calls I made (minor, builder's discretion — поправь, если не так)

- **Раскладка запуска в iTerm2:** по умолчанию — **одно окно на проект, новая вкладка
  на каждого агента** (естественно ложится на «3 агента в проекте = 3 вкладки»).
  Легко поменять на «панель-сплит» или «окно на агента» позже.
- **Рабочее имя продукта — «Deck».** Косметика, переименуется в любой момент.
- **Папки состояния:** `~/.deck/` (events.jsonl, реестр). Можно сменить.
- **Хук — shell-скрипт** (без node), чтобы не плодить зависимости.

## Left to the builder

- Точные глаголы AppleScript для создания/фокуса сессии iTerm2 (и фолбэк на Python API,
  если `select` панели окажется ненадёжным).
- Схема JSON-события и формат реестра.
- Иконка/бейдж агрегатного статуса и визуальный язык статусов.
- Дебаунс активности, чтобы строка «чем занят» не мерцала на частых PreToolUse.
